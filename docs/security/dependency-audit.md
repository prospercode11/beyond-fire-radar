# Phase 10 dependency audit

The release audit runs `pip check`, audits the declared runtime dependency set plus the PostgreSQL, Redis, and S3/R2 release extras with `pip-audit`, and runs `npm audit --audit-level=high`. The script intentionally excludes the editable local project and development/security-tool transitive packages from the runtime audit so the result describes the production dependency boundary.

On 2026-08-02, npm reported `found 0 vulnerabilities`. The Python audit reported 18 advisories across urllib3, Starlette, python-multipart, click, and python-dotenv when the PostgreSQL/Redis/S3 release extras were included. The current package index did not expose all listed fix versions for the supported Python 3.9 audit environment. The advisories are explicitly reviewed rather than silently ignored:

- Starlette host/path advisories are mitigated for this application by explicit trusted-host enforcement; authentication does not derive authorization from a reconstructed URL, no `StaticFiles` or raw `HTTPEndpoint` surface is registered, and request/body limits are enforced at the API boundary.
- python-multipart path traversal configuration is not used (`UPLOAD_DIR` and filename-preserving disk upload behavior are absent). Multipart inputs are bounded by request and per-upload limits, then passed through the application filename/suffix checks. Parser DoS advisories remain an upstream availability watch item until a compatible patched release is available.
- click is a development/CLI transitive dependency and the affected `click.edit()` function is not used by the API or release scripts.
- python-dotenv is used for settings loading; the affected symlink-following mutation helpers are not called by the application. `.env` files are deployment inputs and are not rewritten by the service.
- urllib3 advisories are reviewed against the actual call boundary: the application does not call the affected low-level proxy redirect or streaming/decompression controls directly, and the S3 adapter delegates transport to boto3 while verifying content hashes. The Python 3.9 audit resolver selects urllib3 1.26.x for the optional boto3 dependency; the release image targets Python 3.12, and the available package index did not expose urllib3 2.7.0 for this audit host. This remains a pre-deployment upgrade watch item, not a blanket acceptance of an unbounded HTTP client.

The allowlist in `scripts/dependency_audit.sh` is exact-ID based, has a Release Engineering owner and a 2026-09-01 review deadline, and fails on any new advisory. It is not a blanket vulnerability suppression. The Phase 10 gate therefore has no unreviewed finding in an exercised application path, while the upstream advisories above remain a recorded limitation and must be re-audited before deployment.
