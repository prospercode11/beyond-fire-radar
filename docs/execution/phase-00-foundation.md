# Phase 0 — Repository audit and architecture

## Objective

Make the product boundary, architecture, compliance posture, data contracts, modeling rules, test gates, and later execution plan explicit before broad implementation.

## Deliverables

- Product specification.
- Architecture decision record.
- System context/data flow and foundation data model.
- Threat model.
- Modeling specification with calibration and abstention rules.
- Compliance boundaries and source registry.
- Data dictionary and evaluation plan.
- Master checklist and current state.
- Phase task files for Phases 2–10.

## Acceptance gate

The repository has a documented modular-monolith decision, explicit Phase 1 boundary, no automatic outreach scope, source authorization rules, a provenance/data model, future model contracts, test/evaluation requirements, threat controls, and a task file for each later phase. This gate is satisfied by the documents in this commit.
